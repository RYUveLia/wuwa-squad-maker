# 커뮤니티 업데이트 공지

배포가 끝난 기능 변경을 커뮤니티에 알리는 글을 만든다. **버전 업데이트 작업과는 별개**이며, 사용자가 요청할 때만 진행한다. (사용자가 직접 올릴 수도 있음)

## 산출물

1. 펨코 제목 + HTML 본문
2. 아카라이브 제목 + HTML 본문
3. 스크린샷 (운영 사이트에서 캡처)

템플릿: [`templates/fmkorea.html`](templates/fmkorea.html), [`templates/arca.html`](templates/arca.html)
지난 글 예시: [`examples/`](examples/) (2026-11-06 버전별 편성 공지)

## 진행 순서

### 1. 무엇을 알릴지 정리
- 머지된 PR/커밋에서 **사용자가 체감하는 변화만** 고른다. 내부 리팩토링·테스트는 빼거나 "사이트 안정성 개선" 한 줄로.
- 버전 데이터만 바뀐 경우(유출 공명자·회로·시즌 버프)는 짧은 글로 충분 (아래 "글 유형" 참고).

### 2. 원글 형식 확인 (중요)
문구만 맞추지 말고 **글씨 크기·굵기·빈 줄·이미지 너비**까지 원글과 맞춘다. 형식이 바뀌었을 수 있으니 최근 글의 HTML을 확인한다.
- 아카라이브는 일반 요청(WebFetch)이 403 → Playwright 등 실제 브라우저로 열어야 함
- 확인 방법: 본문 요소(`.xe_content` / 아카 `.article-body .fr-view`)의 innerHTML과 각 문단 computed `font-size`

| 항목 | 펨코 | 아카라이브 |
|---|---|---|
| 게시판/분류 | 명조 게시판, 말머리 **정보** (유출 데이터만 반영한 짧은 글은 **유출잡담**) | 명조 채널, **공략/정보**, 시리즈 "매트릭스 파티 메이커"에 추가 |
| 말투 | 짧은 반말("~함/~됨"), 인사·맺음말 없음 | 존댓말, "안녕하세요." 시작 → "즐거운 매트릭스 되시길..." 끝 |
| 본문 글씨 | 기본 크기 | **15px, 줄간격 2** (모든 문단) |
| 강조 | "PC, 모바일 가능" **24px 굵게**, "수정사항" 굵게 | "PC, 모바일 가능합니다" **24px** (굵게 아님), 소제목은 15px 일반 |
| 빈 줄 | 블록 사이 `<p><br></p>`, 목록 항목 사이엔 없음 | 문단마다 `<p><br></p>`, 섹션 사이 2줄 |
| 마지막 | `이전글: <최근 펨코 글>` | (시리즈 박스가 자동 연결) |

### 3. 제목
- **펨코**: `종말 매트릭스 파티 메이커 업데이트! (<핵심 한 줄>)` / 짧은 데이터 반영 글은 `종말 매트릭스 파티 메이커 업데이트`
- **아카**: 최근 시리즈 형식 `(유출 정보 있음) <상황/계기>, 매트릭스 파티 메이커`
  - 예: `(유출 정보 있음) 릴리가 테섭에 나왔을 때, 매트릭스 파티 메이커`
  - 사이트에 유출 데이터가 있으면 `(유출 정보 있음)` 필수

### 4. 스크린샷
[`scripts/capture-screenshots.cjs`](scripts/capture-screenshots.cjs)로 **운영 사이트**(배포 완료 후)에서 캡처한다. repo에 Playwright 의존성을 넣지 않기 위해 임시 폴더에서 실행:

```bash
mkdir -p /tmp/wuwa-shot && cd /tmp/wuwa-shot && npm init -y >/dev/null && npm i playwright@1.58.2 && npx playwright install chromium
# 스크립트는 repo에 있고 playwright는 임시 폴더에 있으므로 NODE_PATH 필수
NODE_PATH=/tmp/wuwa-shot/node_modules node <repo>/.agents/skills/community_announcement/scripts/capture-screenshots.cjs \
  --out /tmp/wuwa-shot/out --other 3.7 --mobile 3.7
```

- `--board`: 메인·이미지 저장에 쓸 보드 (기본: 예시 세트의 세트 추천 버전) / `--other`: 다른 버전 코드 선택 창을 띄울 보드 (board와 달라야 함) / `--mobile`: 모바일 캡처 버전

| 파일 | 내용 | 펨코 너비 | 아카 너비 |
|---|---|---|---|
| `1-main.png` | 메인 (버전 탭 + 보드) | 794px | 가로 꽉(902px) |
| `6-mobile.png` | 모바일 | 390px | 390px |
| `2-migration.png` | 기존 파티 이관 창 | 600px | 640px |
| `3-import-choice.png` | 다른 버전 코드 선택 창 | 450px | 450px |
| `5-import-modal.png` | 불러오기 창 | 450px | 450px |
| `4-image-export.png` | "이미지로 저장" 실제 결과 | 600px | 640px |

- 2배 해상도로 캡처되므로 **작은 창 이미지는 반드시 너비를 지정**한다 (안 하면 본문 폭만큼 커짐).
- 예시 파티는 [`scripts/sample-squads.json`](scripts/sample-squads.json) (3.6 세트). 새 기능에 맞는 장면이 필요하면 스크립트에 단계를 추가한다.
- 기능에 따라 필요한 장면만 고른다. 데이터만 바뀐 글은 `1-main.png` 하나면 충분.
- 캡처 후 **이미지를 직접 열어서** 잘림·토스트 가림·전환 중 흐림이 없는지 확인한다.

### 5. 본문 작성
- 템플릿의 `{{...}}`를 채운다. 아카의 "이용 방법"·"기능" 섹션은 기능이 바뀐 경우만 수정.
- 이미지 자리는 `[이미지: 파일명 → 너비]`로 남겨 두고, 사용자가 업로드한 뒤 HTML을 다시 주면 `<img ... style="width: Npx; height: auto;">`로 너비를 넣어 최종본을 만든다.
- 같은 문장이 두 번 들어가지 않았는지 확인 (업로드 중 중복이 생기기 쉬움).

### 6. 게시 이력 갱신
게시 후 아래 표에 URL을 추가한다 (다음 글의 "이전글"·시리즈 연결용).
